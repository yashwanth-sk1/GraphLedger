# CLAUDE.md

Guidance for Claude (or any AI coding assistant) working in this repository.

## What this project is

GraphLedger is a **working SIH prototype** — not a production system —
that follows the movement of value across banks, crypto exchanges/wallets,
and NFT marketplaces/assets as one unified temporal transaction graph.
It uses deterministic rule-based detection (explicitly NOT a trained ML
model), a weighted explainable risk score, and a local SHA-256
hash-linked ledger. Everything runs locally via Streamlit with no
external services, no real financial data, and no network calls out.

Read `README.md` first for the full feature list (IMPLEMENTED NOW vs.
FUTURE ROADMAP), and `DEMO_NOTES.txt` for how this maps to SIH judging
criteria.

## Module map

| File | Responsibility |
|---|---|
| `app.py` | Streamlit UI only: tabs, filters, sliders, rendering. Should not contain detection logic. |
| `analytics.py` | `normalize_transactions`, time/velocity helpers, `TemporalChain`, `find_temporal_chain` / `find_cross_entity_chain`, all `detect_*` rules, `calculate_risk_score`, `run_all_detectors`, `build_velocity_table`. |
| `graph_utils.py` | `build_transaction_graph`, `render_graph` (Plotly, entity-type colored). |
| `ledger.py` | `build_ledger`, `verify_ledger` — the tamper-evident hash chain. |
| `generate_data.py` | Synthetic multi-domain dataset generator (bank/crypto/NFT scenarios). |

Keep this separation. If you're tempted to put a new detection rule
inside `app.py`, put it in `analytics.py` instead and call it from
`app.py`.

## Ground rules when modifying this repo

1. **Keep it runnable in one command.** `pip install -r requirements.txt &&
   streamlit run app.py` must always work from a clean checkout. Don't
   introduce dependencies that need external accounts, API keys, Docker,
   or a database server.
2. **Never introduce real financial data.** All bank names, account IDs,
   wallet addresses, exchange names, NFT IDs and transactions must stay
   synthetic and generated by `generate_data.py`. Do not wire up real
   banking/crypto/NFT APIs, and do not import data from uploaded
   complaints, screenshots, or real transaction records, even "for
   realism." Crypto/NFT prices must stay fixed synthetic demo values,
   clearly labeled as such — never live market prices.
3. **Don't overstate what's implemented.**
   - The hash-linked ledger is a "Tamper-Evident / DLT-inspired local
     ledger prototype." Never call it Hyperledger Fabric, a permissioned
     blockchain, or a live blockchain unless that is actually built.
   - The detection engine is deterministic rules. Never call it
     "AI model" or imply a trained ML model exists — use "Rule-Based
     Graph Intelligence Prototype" or "AI/Graph Intelligence" (as a
     category description, not a claim of a trained model).
   - NFT repeated-trading / price-escalation alerts must stay phrased as
     "potential" / "pattern signal," never as confirmed wash trading.
4. **Prefer small, demoable increments.** This is judged live. A feature
   that partially works and is visible in the UI beats a larger feature
   that's half-wired.
5. **No secrets, no telemetry.** The app should never require an API key,
   phone home, or write outside its own `data/` directory.
6. **Preserve backward compatibility.** `normalize_transactions()` in
   `analytics.py` must keep working against an old bank-only CSV
   (missing crypto/NFT columns) without crashing. If you add a new
   required-looking column, add a default for it there too.
7. **Time windows stay configurable**, not hard-coded. New detection
   rules should take a window/threshold as a parameter (see the
   `DEFAULT_*_SECONDS` constants in `analytics.py`) and, where relevant,
   get a corresponding slider in `app.py`.

## Typical tasks you might be asked to do here

- **Add a new detection rule** → add a `detect_*` function in
  `analytics.py` following the existing pattern (build a `TemporalChain`
  via `find_temporal_chain`/`find_cross_entity_chain`, call `make_alert`),
  then add it to `run_all_detectors()` and to the weighting logic in
  `calculate_risk_score()`.
- **Add a new synthetic scenario** → extend `generate_data.py` with a new
  labeled `scenario` value, keep `random.seed(42)` fixed, and make sure
  `normalize_transactions` + existing detectors handle it without new
  special-casing where possible.
- **Add a new entity type** → add it to `ENTITY_DOMAIN` in `analytics.py`
  and `ENTITY_COLORS` / `ENTITY_LABELS` in `graph_utils.py`.
- **Improve the graph visualization** → edit `graph_utils.render_graph`.
  It currently uses Plotly (already a dependency) for interactivity —
  keep it dependency-light; don't add a separate JS frontend build step.
- **Extend the risk score** → add/adjust a bucket in
  `analytics.COMPONENT_CAPS` and the corresponding branch in
  `calculate_risk_score()`. Keep the total capped at 100 and each
  component capped and explainable.
- **Wire toward a real ledger/DLT** → keep `ledger.py`'s hash-chain code
  as the reference implementation and add an adapter layer rather than
  replacing it, so the local demo still works without any external chain
  running.

## Testing changes before a demo

There's no formal test suite (intentional, for prototype speed). Before
a live demo, always manually smoke-test:

1. `python generate_data.py` runs with no errors and reports all 9
   scenarios.
2. `streamlit run app.py` starts with no errors (check the terminal for
   tracebacks, not just that the page loads).
3. Overview tab shows non-zero banks/wallets/exchanges/NFTs/transactions.
4. Transaction Graph tab renders with a legend and at least one red node.
5. Risk Alerts tab shows alerts across bank, crypto, NFT, and
   cross-ecosystem types (not just one category).
6. Investigation tab: selecting a wallet from the multi-wallet chain
   shows a non-zero velocity and a connected-path table.
7. Ledger Verification tab: "Build / Verify Ledger" reports a valid chain.
8. Moving a sidebar threshold slider changes the alert count.
9. "🚨 Simulate Suspicious Network" adds a visibly new red path and alert.
10. Loading an old bank-only CSV (missing crypto/NFT columns) does not crash.
